## Qué se hizo

- `src/domain/agenda/estados.ts` (puro): tabla de transiciones `reservado → confirmado | cancelado | ausente | atendido`, `confirmado → cancelado | atendido | ausente`; `cancelado`, `atendido` y `ausente` son finales. `validarTransicion` devuelve `Result`; una transición inválida (incluida la transición al mismo estado) es `RN-AG-09` con `conflicto.turnoId` = el propio turno (DD-08).
- `src/domain/agenda/ventanaCancelacion.ts` (puro): el paciente cancela si faltan **24 h o más** (24 h exactas es válido); recepción y admin siempre (RN-AG-06). Recibe `ahora: Date` desde la capa de aplicación (`clock.ahora()`). Exporta `VENTANA_PACIENTE_MS` para reusar en C-04.
- `src/application/agenda/cambiarEstadoTurno.ts`: confirmar / atender / ausente con helper compartido (rol → turno existe → odontólogo dueño del turno → RN-AG-09), persiste y audita con antes/después (RN-AU-01).
- `src/application/agenda/cancelarTurno.ts`: orden rol (403) → motivo (400) → turno existe (404) → propiedad (403) → RN-AG-09 (409) → RN-AG-06 (409). Guarda `motivoCancelacion`, `canceladoPor`, audita y devuelve el evento `turnoLiberado`; lo publica si se inyecta un `PublicadorEventos` opcional.
- `src/api/routes/turnos.ts` (aditivo, al final del router): `POST /api/turnos/:id/confirmar | atender | ausente | cancelar` → 200 / 400 / 403 / 404 / 409. El 404 se responde en la ruta con la misma forma JSON que el 404 de `/api`.
